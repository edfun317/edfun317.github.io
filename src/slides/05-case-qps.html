案例一 / 下注交易系統重構

先拆解資料職責，再配置獨立資源

Situation

  • •尖峰 7,000 QPS 即不穩
  • •Loading 大幅波動
  • •Secondary 複製落後
  • •連線與 goroutine 堆積

Task

  • •找出根因
  • •穩定尖峰承載

Action

監控波動 ➔ Secondary 落後 ➔ 排除連線池 / 讀寫分離
根因

單一 collection 同時扛寫入與查詢，Secondary 追不上 oplog

決策
  • •依職責拆 狀態 / 投注 / 贏分，各配獨立機器
  • •狀態走狀態機驗證
  • •完成即刪，資料量最小化
  • •成單改非同步；導入冪等性可重送補單
Result
7,000 不穩 ➔ 8,000+ 穩定 事故未再發生 複製延遲消除
