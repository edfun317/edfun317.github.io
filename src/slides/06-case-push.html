案例二 / 全公司推播系統收攏

跨部門整併，從零打造高承載推播平台

Situation

  • •執行長要求將既有推播收攏為單一系統
  • •舊系統分散在各部門，各自維護

Task

  • •盤點全公司相關服務
  • •確認各部門待收攏的訊息系統
  • •開發新的推播系統

Action

技術選型
  • •服務已在 GCP，Pub/Sub 整合成本最低
  • •Subscription 的機制符合應用場景，壓力測試過後覺得表現符合期望
吞吐設計
  • •以批次為發布單位，佇列訊息數大幅降低
  • •固定大小 goroutine pool 消費，避免打爆下游
  • •批次寫入取代逐筆，降低 DB round trip
遷移策略
  • •提供相容層 / API，降低各部門遷移成本
  • •新舊並行雙寫比對，確認無誤才切換
可靠性
  • •確認寫入完成才 Ack，避免 Worker 被回收時遺失訊息
Result
達成每分鐘 20 萬筆推播 K6 壓測穩定 30 萬筆／分 跨部門推播收斂為單一平台
